# 生成与维护

## 操作流程

网页保存项目 JSON；生成器解析目标平台、版本号、Boot/App、模块实例和输出设置，校验器件、总线、共享资源及依赖，然后按模板渲染 cfg/def/src，装配工程成员并写入目标目录。不会先把旧目录改名为 temp，也不会直接复制整个旧板级目录。

项目版本号为一个用户输入值，如 R01V02；工具不要求用户分别填写硬件版本和软件版本。运行时间等可推导信息由生成过程提供。可变对象数量由数组确定，不能用示例中的数量限制其他项目。

## 覆盖规则

默认输出目录为 `product/src/brd/<版本号>`；手动目录支持项目相对路径或绝对路径，不限制目录名称和层级，`r01v01` 不再特殊保留。首次生成使用创建模式和新的输出目录。已管理目录仅在明确重新生成模式下更新；用户区按模板标记保留，生成区的人工改动会触发保护错误。需要自定义逻辑时先确认目标模板的用户区标记，不要假设任意注释都能被识别。

本机状态和报告存放在 `.reports/generation/<目录名>/`（自定义位置附加路径摘要，避免同名目录的状态冲突）。其中 `.pbrd-manifest.json` 参与后续更新，删除状态后应输出到新目录再比较，不能认为删除缓存能强行接管原目录。报告不进入产品代码，但 `check_list.md` 随产品输出，需要按实际硬件逐项审核。

生成失败时先看界面或命令行错误，再检查 JSON、器件源码、平台规则。不要通过删除保护状态绕过错误。保存并构建失败时，已保存 JSON 仍可用于排查和重试。

## 维护定位

| 变化 | 修改位置 |
| --- | --- |
| 项目实例、引脚和功能 | 网页 / 项目 JSON |
| 模块字段、器件和依赖 | modules/，必要时 ui/frontend-fields.json |
| 数据来源路径 | ui/source-settings.json、pbrd.config.json |
| 引脚复用和平台固定默认值 | platforms/ |
| 命名、注释、初始化布局 | templates/ 与 generator/modules/ |
| 对象关联、实例展开 | generator/modules/ |
| 工程文件与编译成员 | generator/projects/ 与平台 generation 规则 |

兼容旧格式的 `codegen` 参数仍可能出现在旧 JSON 中。当前 v2 页面输入使用正式平台默认值和高层字段，不应从示例 JSON 提取参数充当新模块实现。

工程生成与编译分开验收：打开工程、检查路径、执行工具链编译、比较输出、审核 IO 和硬件行为。Keil 工程能打开或编译成功都不等于板级配置与原理图一致。

## App XCU

AC78428 的 App XCU 支持一个专用 SPI 实例，配置 CLK/SOUT/SIN/CS/REQ、SPI 模式、DMA 和两个线程共用的栈大小。使用 `brd/mcu` 适配及 `hal/xcu/common`，并依赖 `drv.xcu_spi`；不等同于独立 Boot `brd.xcu_spi` 模块。旧 JSON 的结构化 XCU 参数可恢复为表单，未记录的线程栈大小需核对。


## 配置代码约定

实例数组的 count/base_count 由 sizeof(数组) / sizeof(数组[0]) 推导；空对象采用 0/NULL，不生成零长度数组。CAN 每通道配置最多两路公共电源，普通 CAN 电源回调独立于 FD；当前目标无 FD 通道时不包含 FD 专用头文件和实现。外部 RTC 不生成板级枚举定义头，默认使用器件地址宏及驱动内置定时器参数，显式勾选自定义参数时才生成定时器配置。

对象名以器件芯片或功能命名，同款多实例才附序号。默认地址使用芯片宏，自定义地址集中为命名宏；注释集中说明物理引脚、枚举功能、电平和资源关联，不重复注释纯指针映射。Flash 内部写入模式由 section_write 明确指定；默认保留普通模式，Fee 与内部 PFlash 共用互斥锁，事件仅分配给使用外部总线的器件。作者为空时默认为软件工程院。
